# Coach Report — Architecture Plan

## 1. Goal

Add a post-interview **narrative coaching report** that complements the
existing per-question feedback. Today the platform stores rating + short
feedback per answer; nothing aggregates across the interview, so the user
sees no overall narrative ("you showed strong React fundamentals but
struggled with `useEffect` cleanup — here is what to study next").

The coach report is a single, holistic markdown document generated by
Gemini after the candidate has submitted answers. It is **idempotent**:
generated once per interview, cached in Postgres, re-served on subsequent
GETs without re-billing.

Phase 1 (this plan) ships the **non-streaming** version end-to-end. A
Phase 2 will add an SSE streaming variant of the same endpoint without
changing the persistence model.

## 2. Data model

New table — additive only, no changes to existing schema.

```sql
-- migrations/0004_add_coach_reports.up.sql
CREATE TABLE coach_reports (
    id              uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
    mock_id         text        NOT NULL UNIQUE REFERENCES mock_interviews(mock_id) ON DELETE CASCADE,
    content         text        NOT NULL,
    tokens_used     integer     NOT NULL CHECK (tokens_used >= 0),
    model           text        NOT NULL,
    created_at      timestamptz NOT NULL DEFAULT now()
);
```

Conventions follow [backend §3](./backend.md#3-postgres-schema):
- `text` for the markdown payload (no length cap — Gemini reports stay
  under ~8 KB but we don't want a hardcoded ceiling).
- `mock_id` is `UNIQUE` so idempotency is enforced at the schema level,
  not just in app logic.
- `tokens_used` + `model` captured for usage analytics and future cost
  attribution per user.
- `ON DELETE CASCADE` from `mock_interviews` so deleting an interview
  cleans up the report.

No new sentinel errors. Existing `ErrNotFound`, `ErrValidation`, `ErrLLM`,
`ErrConflict`, `ErrUnauthorized` cover all paths.

## 3. Domain types

```go
// backend/internal/domain/coach_report.go
type CoachReport struct {
    MockID      string    `json:"-"`
    Content     string    `json:"content"`
    TokensUsed  int       `json:"tokensUsed"`
    Model       string    `json:"model"`
    CreatedAt   time.Time `json:"createdAt"`
}

// CoachReportSeed is the input the LLM uses to draft the report.
type CoachReportSeed struct {
    JobPosition     string
    YearsExperience int
    Answers         []UserAnswer  // already-evaluated per-question data
}
```

`ClerkUserID` is **not** on the domain type — ownership is derived from
the parent `mock_interviews` row via JOIN at query time.

## 4. LLM contract

Unlike `GenerateQuestions` / `EvaluateAnswer` which use `ResponseSchema`
for structured JSON, the coach report returns **free-form markdown**. The
LLM is more expressive when not constrained to JSON, and the consumer
(frontend) renders markdown directly.

```go
// backend/internal/llm/gemini.go
func (c *Client) GenerateCoachReport(
    ctx context.Context,
    in domain.CoachReportSeed,
) (content string, tokensUsed int, err error)
```

- `ResponseMIMEType: "text/plain"` (default, no schema).
- `Temperature: 0.7` (slightly less random than question gen — we want
  consistent coaching tone).
- Token count read from `resp.UsageMetadata.TotalTokenCount` so we can
  store it; if absent, store 0 and log a warn.
- Wrap any SDK error with `domain.ErrLLM`.

The prompt (see `buildCoachReportPrompt` in [prompts.go](../../backend/internal/llm/prompts.go))
asks for a fixed section structure: **Overall Performance**, **Strengths**,
**Areas to Improve**, **Recommended Next Steps**, **Speaking & Delivery**
(uses the existing `FillerCount`/`WordsPerMinute`/`LongPauseCount` data).

## 5. sqlc queries

```sql
-- name: InsertCoachReport :exec
INSERT INTO coach_reports (mock_id, content, tokens_used, model)
VALUES ($1, $2, $3, $4);

-- name: GetCoachReportByMockID :one
SELECT cr.mock_id, cr.content, cr.tokens_used, cr.model, cr.created_at
FROM coach_reports cr
JOIN mock_interviews mi ON mi.mock_id = cr.mock_id
WHERE cr.mock_id = $1 AND mi.clerk_user_id = $2;
```

`GET` joins through `mock_interviews` so ownership is enforced in SQL —
a not-owned report returns `ErrNotFound` (same as missing), never leaks
existence.

## 6. Service flow

```go
// backend/internal/service/interview.go
func (s *InterviewService) GenerateCoachReport(
    ctx context.Context,
    clerkUserID string,
    mockID string,
) (domain.CoachReport, error)
```

Validation order (per [backend §7](./backend.md#7-error-handling) discipline:
identity → domain → expensive LLM):

1. `clerkUserID` non-empty → else `ErrUnauthorized`.
2. `mockID` non-empty → else `ErrValidation`.
3. `UpsertUser` (lazy JIT).
4. **Ownership + idempotency check**: `GetCoachReport(mockID, clerkUserID)`.
   - If found → return it (no LLM call, no cost).
   - If `ErrNotFound` → continue.
   - Other error → wrap and bail.
5. **Ownership check via parent**: `GetInterviewByMockID(mockID, clerkUserID)`.
   - If `ErrNotFound` → return `ErrNotFound` (caller can't generate report
     for a non-existent or not-owned interview).
6. **Pre-condition**: `ListAnswersByMockID(mockID, clerkUserID)`. If empty,
   return `ErrValidation` ("cannot generate report — no answers submitted").
7. **LLM call**: `llm.GenerateCoachReport(seed)`.
8. **Persist**: `InsertCoachReport(...)`. If `ErrConflict` (race — two
   concurrent generates), swallow and `GetCoachReport` again to return
   the winning one.
9. Return the freshly persisted report.

## 7. HTTP contract

Two endpoints, both under `/api/v1/interviews/{mockId}/coach-report`:

### POST — generate (or return existing)
- Body: none.
- Response 201 (created) or 200 (already existed): `CoachReport` JSON.
- Errors: 400 (no answers), 401, 404, 502 (LLM), 500.

### GET — fetch existing only
- Response 200: `CoachReport` JSON.
- Response 404 if not yet generated.
- Errors: 401, 404, 500.

POST is the user-driven "generate" action; GET is for cheap reloads / SSR
prefetch where a 404 is acceptable signaling.

Router wiring in [router.go](../../backend/internal/http/router.go) extends
the existing `/interviews/{mockId}/...` subtree:

```go
r.Route("/{mockId}/coach-report", func(r chi.Router) {
    r.Post("/", ih.GenerateCoachReport)
    r.Get("/",  ih.GetCoachReport)
})
```

## 8. Testing strategy (TDD, per [backend §8](./backend.md#8-testing))

| Layer | Test type | Key cases |
|---|---|---|
| `store/coach_reports_test.go` | integration (`//go:build integration`) | insert + get round-trip; not-owned returns ErrNotFound; duplicate insert returns ErrConflict; cascade on parent delete |
| `llm/prompts_test.go` | unit | prompt includes job position, all answers, structural anchors ("Strengths", "Recommended Next Steps") |
| `service/interview_test.go` | unit (mocked store + LLM) | idempotency (existing report short-circuits), empty answers → ErrValidation, not-owned → ErrNotFound, LLM failure → ErrLLM, race conflict swallowed |
| `http/interviews_test.go` | unit (mocked service) | 201 on first POST, 200 on second POST (idempotent), 200/404 on GET, ownership 404, 400 on no-answers, 502 on LLM |

Coverage targets stay at ≥80% on `service/` + `store/`. The LLM client
itself is not directly tested (covered through service mocks).

## 9. Out of scope (deferred)

- **Streaming** (SSE): Phase 2. Will add a sibling endpoint
  `/coach-report/stream` that reuses the same prompt + persistence but
  streams chunks. Persistence still happens once at stream completion.
- **Regenerate**: no UI yet for "throw away and regenerate". When needed,
  add `DELETE /coach-report` rather than mutating in place.
- **Multi-language**: report is English-only for now. Locale negotiation
  is a future concern.
- **Token-cost UI**: `tokens_used` is captured but not surfaced to the
  user yet — analytics-only.
